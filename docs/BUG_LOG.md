# Bug log: defects caught in AI-written code

Each entry: what the AI wrote, how it was caught, and what changed. "Caught by" names the
actual mechanism (test, eval, or review step), not a guess.

| ID | Area | What was wrong | Caught by | Fix |
|----|------|----------------|-----------|-----|
| BUG-01 | Serverless proxy | Snapshot fallback used a template-string dynamic import (`import(\`../fixtures/leaderboard-${p}.json\`)`). Serverless file tracing cannot follow a computed path, so the fallback would have crashed in production exactly when it was needed (upstream down). | Self-review of the generated proxy before writing tests. Then locked in by the unit test `falls back to the bundled snapshot when upstream throws`. | Static import map, one literal `import()` per fixture. |
| BUG-02 | CSS architecture | The first draft of `index.css` put the design tokens and element rules inside `@layer base`, the usual shadcn layout. The reference compiles its element overrides (`button{border:none}`, `button:hover{background:transparent!important}`, `*{box-shadow:none!important}`) *after* utilities. With the AI's ordering, every unselected filter button would have shown a border, and hover backgrounds and focus rings would have appeared where the original has none. | Reading the reference's compiled CSS and mapping rule byte offsets (base at 2.6k, utilities from 4.9k, custom globals at 21.8k, variants from 25.3k) before the first screenshot. | Same order: `@tailwind utilities` → unlayered globals → explicit `@tailwind variants`. |
| BUG-03 | Tailwind colours | The AI's default instinct was to define colours as `hsl(var(--x) / <alpha-value>)`, so that `bg-accent/50` and `text-foreground/70` would work. The reference uses plain `var(--x)` colours, which means those classes compile to **nothing** there: row hover does not tint, and the Score label is full-strength. "Fixing" this would have made the replica look different. | Grepping the reference CSS for `.hover\:bg-accent\/50`: missing. | Kept plain `var()` colours on purpose, with a comment in `tailwind.config.js`. |
| BUG-04 | Number formatting | Unit tests expected negatives as `-$42.50`. They failed: the code printed `$-42.50`. | Unit tests (`format.test.ts`, 3 failures). | Checked the reference source. It also prints `$-42.50` (it adds a `+` only for >= 0 and leaves the minus inside the number). The code was right and the **test assumption** was wrong, so the tests now pin the reference behaviour, with a comment. |
| BUG-05 | Test arithmetic | `downsampleDaily` test expected <= 21 points; got 22. | Unit test failure. | Recounted: 80 × 6h from Jan 1 06:00 ends Jan 21 00:00, which is 21 UTC days plus the kept first point = 22. The test now asserts exactly 22 and 21 distinct days. |
| BUG-06 | Eval harness | Visual scores came back at 100.00% on 8 of 10 cases. A perfect score can also mean a broken metric (for example comparing a page with itself, or two blank screens). | Treating "too good" as a red flag. Opened the screenshots, then added a **negative control**: inject a 2px padding change into the replica only. | The control scores 92.21% and fails the 97% gate as intended, which shows the metric detects a 2px shift. The control now runs on every eval. |
| BUG-07 | Eval harness | "All columns" case scored 99.66%. The diff mask showed only avatar circles differing. | Inspecting the diff image (`/compare`, Diff mask). | Lazy images had not loaded after the period switch. The harness now scrolls and re-waits for images after interactions. This was a timing issue, not a layout one. |
| BUG-08 | Eval harness | Every `page.evaluate` in the parity eval threw `ReferenceError: __name is not defined` on both sites. | Parity eval output (22 errors). | tsx/esbuild wraps named functions with a `__name` helper, which does not exist in the browser. Fixed by defining a no-op `__name` via init script. |
| BUG-09 | Eval harness | Calendar expand click timed out. | Parity eval. | The generated selector targeted an SVG `<path>`. Playwright clicks need a hit-testable box, so the selector now targets the `<svg>`. |
| BUG-10 | Tooling | Playwright 1.48's Chromium (r1140) failed to launch on this macOS (`spawn Unknown system error -88`). | First eval run. | Matched browser revisions to installed builds and pinned `@playwright/test@1.64.0` (Chromium r1248). |
| BUG-11 | Compliance | The first proxy draft forwarded predicting.top data with no attribution. predicting.top's API docs ask consumers to credit and link back. | Reading the full API docs page while mapping endpoints. | Credit and link on `/replica`, in the README and in the badge tooltip. Edge caching (`s-maxage=30`) keeps upstream traffic far below their published 100–120 req/min limits. |
| BUG-12 | Ethics / correctness | Re-implementing link helpers verbatim would have carried predicting.top's affiliate codes (`?via=unbroken0x`, `?referral=predictingtop`) into a site that is not theirs. | Review of `referral-*.js` while porting link logic. | Outbound links are stripped of referral params (`stripTracking`). Unit-tested. |
| BUG-13 | Honesty | Porting the Terms page verbatim would have published predicting.top's legal terms (naming their operators) on a different site. Porting "Get listed" verbatim would have shown "Thanks, we got it." while sending nothing. | Review before porting each static page. | Same layout, replica-specific wording. The form validates exactly like the original but says plainly that nothing was sent. |

## Process notes
- Every bug above was found by a test, an eval, or a deliberate review step: none was reported by a user.
- Two "failures" (BUG-04, BUG-05) were wrong *tests*, not wrong code. The rule is to check the reference before changing either side.
